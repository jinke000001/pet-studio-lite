## 1. 产品目标

交付一个个人自用的 Pet Studio Lite 完整 MVP。macOS 是制作环境，Windows 是优先产品平台。

制作台必须完成这条闭环：

`导入宠物包 → 自动检查 → 动作预览 → 配置 → 导出 Windows 便携 ZIP → 用户解压后双击 EXE 运行桌宠`

最终 Windows 桌宠必须离线独立运行，不依赖 Petdex、Codex、Kimi、VPN、网络、Node.js、Python或任何开发环境。

## 3. 用户可见功能

### 3.1 导入

- 制作台提供清晰的中文界面，可选择本地宠物目录或 ZIP。
- 输入至少包含 `pet.json` 和一张 PNG 或 WebP spritesheet；允许合理兼容常见文件名。
- 导入时复制到应用自己的版本化工作区，不原地修改输入。
- 最近项目或当前项目可以在重启后恢复；损坏状态不得导致白屏或无法重置。

### 3.2 检查

- 支持 Petdex v1：8 列 × 9 行、单格 192×208、完整图集 1536×1872。
- 支持 Petdex v2：8 列 × 11 行、单格 192×208、完整图集 1536×2288。
- 以真实 `spriteVersionNumber` 为主，同时可以兼容明确、无冲突的旧别名；字段冲突、不支持值和尺寸不匹配必须拒绝。
- 检查缺文件、JSON 语法、必要字段、图像可解码性、版本、尺寸和包内路径。
- ZIP 必须防止绝对路径、`..` 逃逸、符号链接/特殊文件、重复目标、异常膨胀和任意文件覆盖；解压失败不得留下被当作成功项目的半成品。
- UI 用用户能理解的中文说明错误位置与修复方向，不显示静默白屏。

### 3.3 预览

- 制作台内能预览图集动作，至少可切换或播放可用状态。
- 能启动真实透明、无边框、置顶的桌宠预览窗口，不允许用普通网页或静态图片冒充。
- 预览加载失败时制作台可见报错，并能重新选择或返回。

### 3.4 配置

- 至少支持宠物显示名称、缩放比例和一个基础行为开关（例如闲逛）。
- 输入有明确范围和即时校验；非法值不能进入 main process 状态或导出配置。
- 配置在项目重启后保持，并进入导出的独立桌宠。

### 3.5 导出

- 在制作台中选择输出位置并导出新的、非覆盖的 Windows x64 便携 ZIP。
- ZIP 解压后顶层有清晰的启动说明和可直接双击的 `.exe`；不得要求安装 Node.js、Python、Git 或运行命令行。
- 运行时与宠物资源共同封装，不能在首次启动时下载依赖。
- 连续两次导出不能静默覆盖前一份产物；失败或取消时不得留下看似成功的 ZIP。
- 产物包含 manifest，记录产品版本、宠物身份、Petdex 版本、原始包 SHA-256、spritesheet SHA-256、导出时间、平台/架构和授权状态。
- 仅授权状态为 `authorized` 的宠物允许生成可分发候选；`internal-test` 可生成明确标记的内部测试候选；`unknown` 必须阻止候选导出并给出中文提示。
- 若 macOS 环境客观无法生成可用 Windows 二进制，必须交付可复现的最近状态、真实错误和明确边界，不能用空壳、伪 EXE 或仅源码 ZIP 冒充完成。

### 3.6 导出的桌宠基础互动

- 透明、无边框、置顶显示，透明区域不出现矩形底色。
- 可拖动移动。
- 单击产生可见动作或本地气泡反馈，不访问网络。
- 右键菜单或托盘菜单至少包含缩放、设置/信息和真正退出。
- 缩放保持窗口底部中心锚点，并夹紧当前显示器 workArea；100%→200% 时不跳离屏幕。
- 退出必须真正结束进程，不仅隐藏窗口或留在托盘。

## 4. 独立产品与数据安全边界

- 使用全新的产品名、package name、`appId`、可执行文件名和 userData 命名空间；不得沿用 `nom` 或其他已安装产品身份。
- 严禁读取、迁移、清洗、重写或删除 `~/.nom`、`~/.codex`、`~/.petdex` 中的状态。用户主动选择其中某个宠物包时，只能只读导入副本。
- 应用自己的项目、缓存和设置只写入自己的 userData；测试使用显式临时目录注入，不通过改写 `HOME` 模拟。
- `contextIsolation: true`、`nodeIntegration: false`。Electron API 留在 main，preload 仅暴露实际需要的窄桥。
- 所有 IPC 参数在 main process 做运行时校验：路径、枚举、字符串长度、boolean、有限数字、对象形状和调用时序。TypeScript 类型不能替代运行时校验。
- renderer 不获得文件系统、shell、任意 IPC 或 Node 权限；外部链接与路径打开只允许明确动作和受控目标。
- 不加入账号、遥测、Token、AI 对话、语音、自动更新、开机启动或网络服务。

## 5. 视觉和体验标准

- 界面为简洁、克制、有明确层级的桌面工具，不套用通用 SaaS 仪表盘模板。
- 主流程在一个清晰的步骤结构中完成；首次使用者无需读代码或猜按钮顺序。
- 有空状态、进行中、成功、失败和可恢复状态；耗时导出有进度或明确反馈，防止重复点击。
- 中文文案一致，不残留 AI Token、transcript、journal、soul 等旧产品概念。
- 窗口在常见 macOS 桌面尺寸下不出现关键按钮被遮挡、横向溢出或不可滚动内容。

## 6. 工程与测试要求

- 尽量沿用上游成熟部分，但以完成上述产品闭环为准，不要求保留无关兼容性。
- 核心导入、校验、项目存储、配置、几何和导出逻辑应与 UI 分离并可自动测试。
- 至少覆盖：合法 v1/v2、版本字段冲突、非法 JSON、错误尺寸、图像不可解码、ZIP 路径逃逸/重复/膨胀、输入不被修改、授权门、非覆盖导出、IPC 非法类型/数值、缩放底部中心与屏幕夹紧、退出语义、旧数据目录不被触碰。
- 执行仓库真实存在的 test、typecheck、lint、build 和安全审计；缺少某项可以补充或如实说明，不能伪造结果。
- 用至少一个 v1 和一个 v2 fixture 跑通导入到预览；fixture 不使用无授权私有素材。
- 在 macOS 实际运行制作台和透明桌宠，人工检查主流程、点击、拖动、缩放、错误恢复和退出。
- 对生成的 Windows ZIP 做静态检查：能解压、EXE 存在、资源/manifest 存在、没有开发机绝对路径、没有运行时外部依赖说明。Windows 动态行为仍必须标记为未实机验收。
