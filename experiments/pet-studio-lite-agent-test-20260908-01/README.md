# Pet Studio Lite 代理对比实验 01

## 目的

用同一份上游代码、同一份任务书和同一套评分标准，先让 Kimi Code 独立完成任务；Codex 额度恢复后，再从完全相同的上游提交独立完成一次。两边不得读取对方的实现或报告。

这次是顺序盲测，不是同时并行。顺序不会影响可比性，关键是固定基线、隔离目录和不交叉参考。

## 本轮只做什么

只做“Windows 产品所需的离线桌宠运行内核”第一个纵向切片：读取 Petdex v1/v2 包、校验、显示预览并完成基础桌宠互动。macOS 是本轮开发和预览环境；不得把 macOS 运行结果写成 Windows 已验收。

本轮不做 Studio 完整编辑器、不做安装器、不做客户素材生成、不做商业发布、不做 60 项 Windows 验收。

## 文件

- `KIMI-START.md`：给用户的逐步操作说明。
- `KIMI-PROMPT.md`：完整任务书，原样交给 Kimi。
- `SCORECARD.md`：人工体验与工程结果记录表。
- `RUN-RECORD.md`：本次实际运行记录，完成过程中填写。

## 公平性规则

1. Kimi 只能读自己的工作目录和这份任务材料，不能读未来 Codex 目录。
2. Codex 以后只能从固定上游提交重新开始，不能读 Kimi 工作目录或报告，直至交付完成。
3. 不把响应篇幅、代码量或“说得像完成了”计为成绩，只看可复现结果。
4. 两边都允许查官方文档和公共网络资料，但必须在报告中列出关键来源。
5. 人工体验评分由用户在实际运行后填写，不由代理自己给自己打分。
