# Pet Studio Lite 双平台试用与验收

范围：供自己和朋友小范围使用；Mac/Windows 工作台，导出 Windows x64 桌宠。无项目互通。appId `com.petstudio.lite`、名称 `pet-studio-lite`、原 userData/studio-data 保持不变。

## 普通使用

当前 Mac 生成的 Windows 候选为 ZIP：解压后运行 Pet Studio Lite.exe。普通用户无需 Node.js、Git、Codex 或 Python。开发者在 Windows 本机运行 npm run package:win 后会生成安装程序和 ZIP。当前 Mac 候选是 Apple Silicon（arm64）DMG。在线下载 Petdex 素材需要联网；导入本地素材、配置、预览及导出可以离线完成。

这是未完成 Windows 实机验收的内部候选。Windows 候选尚未使用发布者证书签名；Mac 仅作本地 ad-hoc 签名，尚未公证，跨机打开可能需要在系统隐私与安全设置中确认。先由作者验证再交朋友试用。不要替换历史已验收版本或手动删除用户数据。

## Windows 11 首轮检查

把完整候选目录复制到本机，打开 PowerShell，在候选目录运行（数字按 Windows 当前实际缩放填写）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\check-windows-studio.ps1 -CandidateDirectory . -ExpectedDpiPercent 100
```

脚本核验候选哈希、Windows 原生解压、EXE 名称版本和内置运行时，使用隔离数据并清空子进程 PATH 启动工作台。根据提示实际完成操作后填写 p/f/s。它不会把未执行项目标为通过，也不会结束其他应用。完成后返回新生成的 `RETURN-studio-*` 目录；其中保留 `candidate.snapshot.json`、候选与 EXE/模板实际哈希、日志和结果。

脚本会在 RETURN 目录生成带 BOM 的 `restart-isolated.ps1`。本轮验收中关闭、重启、重复启动和单实例检查都只能使用这个入口，不要直接双击普通 EXE，否则会进入真实用户数据目录。另开一个 PowerShell，进入本次 `RETURN-studio-*` 目录后运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\restart-isolated.ps1
```

验收安装版时不要让安装程序自动启动应用；找到安装后的 `Pet Studio Lite.exe`，仍通过同一入口启动并复用工作台测试数据：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\restart-isolated.ps1 -WorkbenchExe 'C:\安装路径\Pet Studio Lite.exe'
```

检查导出的桌宠时也使用同一入口，并传入本次导出的 EXE；它会使用另一份隔离桌宠数据：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\restart-isolated.ps1 -PetExe 'D:\本次导出\PetLitePet.exe'
```

隔离入口每次都使用空 PATH、移除 `ELECTRON_RUN_AS_NODE`，并登记启动 PID。退出检查覆盖脚本首次启动和隔离入口后续启动的全部记录 PID；仍有记录进程时只会标为 incomplete。

## 发给 Windows Codex 的任务

> 这是 candidate.json 所标识的 Pet Studio Lite 双平台工作台候选。请先阅读此目录的 candidate.json 和本说明，只操作当前候选和新建的测试数据，不覆盖历史包、不修改用户现有 userData。使用 exec_command 启动交互脚本时设置 tty=true 保留输入通道；先运行 check-windows-studio.ps1，记录当前 Windows 11 x64、实际 DPI、安装包和 ZIP SHA-256。脚本运行期间的关闭、重启、重复打开与导出桌宠运行都只用 RETURN 目录内的 restart-isolated.ps1，禁止直接双击 EXE。检查真实安装版（不仅 ZIP 版）的本地导入、官方在线下载并确认、配置保存与重启保留、预览和导出。导出的桌宠必须实际运行。视觉、动画、拖动、菜单和尺寸感觉由用户确认，不自动代填。分别验证 100/125/150% 缩放、动态切换和有条件时的多屏；验证关闭工作台时预览退出、重复启动仅激活现有实例、60 分钟使用。用新建测试账号/隔离测试数据验证安装/升级/卸载重装；没有上一版 Windows 安装基线时明确记录升级未验证，不伪造升级通过。发现问题先保留 stdout/stderr/result、candidate.snapshot.json 和确切包哈希，查明首个失败，不反复重跑全部矩阵或改写失败记录。报告 pass/fail/blocked/incomplete 和待人工项。

## 开发构建

开发构建使用 Node.js 22.18 或更高版本。依赖按 package-lock.json 固定安装：

```powershell
npm ci
npm test
npm run typecheck
npm run smoke:studio
npm run package:win
```

Mac 对应 `npm run package:mac`，默认当前 Mac 架构；Mac 生成 Windows 便携候选用 `npm run package:win:zip`。Windows 安装程序由 Windows 本机生成，避免依赖 Mac 上的 Intel Wine/NSIS 工具。构建在临时目录安装目标平台依赖，避免覆盖本机 node_modules；生成产物复制到新的版本化 deliverables 目录。代码发生变化后 `npm run prepare:studio` 更新模板，源码模式过期模板会拒绝导出；`npm run dev` 会自动准备。

## 验收边界

Mac 构建、单元测试、安装版回归和 ZIP 静态校验不能替代 Windows 原生窗口/DPI/安装生命周期的证据。每个候选以 candidate.json 的文件 SHA-256 对应实测结果，未验证候选不标正式发布。
