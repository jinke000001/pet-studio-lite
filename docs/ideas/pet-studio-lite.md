# Pet Studio Lite 产品方向

## Problem Statement

现有项目的产品开发与 60 门 Windows 验收高度耦合，个人自用目标被候选绑定、安装器生命周期和跨机证据成本淹没，导致修补周期和沟通成本远高于核心产品价值。

## Recommended Direction

保留原项目、历史候选与证据作为只读资产，新建收缩后的 Pet Studio Lite 路线。macOS 负责制作，Windows 是优先产品平台；先稳定一个通用离线运行内核，再由制作台向该内核注入宠物包和配置。第一交付采用便携 ZIP，解压后双击 EXE，不把安装器作为前置条件。

## Key Assumptions

- 使用者主要是用户本人，不需要多租户、账号或商业发布体系。
- 独立桌宠不能依赖 Petdex、Codex、VPN、Node.js 或 Python。
- Petdex v1/v2 的 `pet.json + spritesheet` 是首批输入合同。
- Windows 产品验证必须最终在 Windows 实机完成；macOS 只证明制作流程和候选可生成。
- 成熟开源项目可作为实现基线，但许可证、第三方素材和安全边界必须逐项复核。

## MVP Scope

- 导入本地 Petdex v1/v2 宠物包。
- 检查文件、JSON、版本、图集尺寸和路径安全。
- 预览动作与透明桌宠窗口。
- 配置名称、缩放和基础行为。
- 导出无需开发环境的 Windows 便携 ZIP。
- 桌宠支持拖动、单击动作、缩放和退出。

## Not Doing

- NSIS 安装器、签名、自动更新和正式发布。
- 账号、云同步、商城、收费、DRM 和遥测。
- AI 对话、语音、Token 设置和素材自动生成。
- 旧 Phase 6 的 60 门验收续跑。
- 在第一版加入多宠同时运行或复杂插件系统。

## Open Questions

- M1 完成后，是否确认 `nom-pet` 适合作为最终运行内核基线，还是只吸收其实现经验。
- M2 的导出契约采用“固定运行时 + 资源注入”还是另一种同等稳定的模板方式。
- 便携 ZIP 在 Windows 100%/125%/150% DPI 上的最小真实验收清单。
- 连续完成工程切片、Bug 修复和 UI 打磨三类盲测后，再决定 Kimi/Codex 的订阅组合。

## 2026-09-08 代理实验方法修正

- 早期 Kimi M1 及 Codex 分轮验收返工只作为引导式预演保留，不用于判断全量独立交付能力。
- 正式对比改为把上述 MVP 全范围一次性交给 Kimi：代理自行拆解、实现、修复自身失败和验证，中途不接收 Codex 的定点修复答案。
- Kimi 与 Codex 都从 `nom-pet` 固定提交 `10c7f136d942cc42ae5b2b4d1e3aa6d5994c455a` 的全新隔离目录开始，使用同一份完整任务书，并各自只做一次首次终局验收。
- 首次交付结果冻结；后续返工可评价修复能力，但不能覆盖首次自主成绩。
