# Shimeji Windows 统一验收

本说明同时适用于固定程序生成测试宠物和标记为 `internal-test-only` 的第三方角色候选。先查看同目录 `manifest.json` 确认实际角色；第三方角色只用于个人或内部兼容测试，不代表取得对外分发授权。

## 本轮快速复验（先做这一项）

先只在 Windows **100% 缩放**下运行 5–10 分钟，重点检查此前反馈的四项：

1. 开启“自动游走”，确认行走、窗口跟随和坠落均为连续动画，不会突然换位置。
2. 把宠物分别抛向屏幕顶边、左边和右边；碰撞后应停止横向滑行并下落。
3. 把宠物拖到三条屏幕边缘；可见角色应接触边框，不应隔着约一个身位。
4. 按下文“应用窗口攀爬”步骤摆放记事本，确认出现与 walking 不同的侧墙攀爬动画。

这四项通过后，再进行 125%/150%、双屏和 1 小时长稳验收。

## 自动验收

1. 将测试 ZIP 完整解压到普通英文或中文目录；不要直接在压缩软件内运行。
2. 第一阶段直接双击 `01-run-stage1-100dpi.cmd`；它会自动按 100% + core 档位调用验收脚本，并在结束后保留窗口以便查看结果。若批处理无法启动，在该目录打开 PowerShell 后执行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\Windows统一验收.ps1 -ExpectedDpiPercent 100 -ManualProfile core
   ```

3. `-ExpectedDpiPercent 100` 表示本轮目标是 100% 缩放；后续两轮分别改为 `125` 和 `150`。脚本启动宠物后会读取其实际 DPI，档位不符就立即停止并写入 `failure.txt`，避免在错误缩放下完成整轮测试。
4. 脚本会先读取 `runtime-integrity.json`，复算实际启动的 `PetLitePet.exe` 与 `manifest.json` 的 SHA-256；任一文件不匹配就停止，避免把其他版本的运行结果误记到本候选。随后约 35 秒自动覆盖首次启动、单实例召唤第二只、可见窗口边界、经典自动行为、关闭单只与完全退出。使用 `-ManualProfile core` 时，脚本会在关闭宠物前逐项等待你实际操作并输入 `Y` 或 `N`，每项同时保存截图；不要在提示期间手动关闭宠物。
5. 成功结果保存在同目录的 `acceptance-evidence-win11-dpi100-core-时间` 这类目录中，其中含 `result.json`、自动截图和人工项截图；目录名会按实际 Windows 代际、DPI、人工档位和长稳时长自动标记。`result.json` 会记录实际哈希、完整性记录和结构化人工结论。
6. 分阶段在 Windows 100%、125%、150% 缩放下各执行一次；每份证据目录都保留，不覆盖前次结果。

基础交互通过后，可以让脚本无人值守运行 1 小时长稳模式：

```powershell
powershell -ExecutionPolicy Bypass -File .\Windows统一验收.ps1 -ExpectedDpiPercent 150 -SoakMinutes 60 -ManualProfile core
```

长稳模式每 30 秒记录运行时进程数、可见宠物窗口数、响应状态、总工作集、总句柄数和直属 PowerShell 窗口探测进程数；每 5 分钟自动召唤并关闭一只宠物。结果写入 `result.json`，原始采样另存为 `soak-samples.json`，结束时仍会关闭全部宠物并检查残留进程。运行期间可以反复移动、最小化、恢复或关闭记事本来人工观察平台跟随；不要手动召唤或关闭宠物，以免干扰脚本的生命周期计数。

脚本不需要管理员权限，不联网，不打开或移动其他应用窗口。运行前若已有测试宠物，请先从宠物右键菜单选择“退出全部宠物”。

## 人工视觉与交互项

每个 DPI 档位都确认以下项目，并把异常截图放入对应证据目录：

- 背景完全透明，没有黑框、白底、方形阴影或图集串帧；宠物尺寸和清晰度合理。
- 自动游走、窗口跟随和坠落过程是连续动画，不会突然跳到另一个位置。
- 左键拖动顺畅，松手后按释放方向投掷；撞到屏幕顶边或左右边后停止横向滑行并自然下落，不会贴边平移或丢出屏幕。
- 可见角色能够实际贴到屏幕顶边和左右边；允许气泡使用的透明窗口留白伸出屏幕，但不应在角色与边框之间留下约一个身位的空隙。
- 打开记事本并将其放在宠物行走路径上：宠物能落到窗口顶边、碰到侧边后使用独立攀爬动画；移动、最小化、关闭记事本时宠物会连续跟随或坠落，不悬空。
- 右键菜单可切换“自动游走”、召唤分身、打开 100%–300% 尺寸面板、回到屏幕右下角、关闭当前宠物和退出全部。
- 召唤到 8 只后不再新增；关闭任意一只不会关闭其余宠物。
- 在双屏之间拖动后改变尺寸，宠物 bottom-center 锚点稳定并完整留在当前显示器工作区。
- 使用 `-SoakMinutes 60` 连续运行 1 小时，期间反复移动/最小化/关闭记事本；脚本自动循环召唤/关闭宠物，并确认无崩溃、卡死、残留进程、明显工作集/句柄增长或持续堆积的 PowerShell 探测进程。

## 应用窗口攀爬怎么测

1. 打开记事本并退出最大化，把窗口放在宠物即将行走经过的位置。
2. 将记事本**底边拉到接近任务栏顶部**，保证地面上的宠物身体能实际碰到记事本左侧或右侧；如果窗口悬在半空，宠物会从下面走过，这是正常的。
3. 打开“自动游走”，让宠物从地面走向记事本侧边。碰撞后应贴着侧边向上移动，并显示独立攀爬帧；到顶后落在记事本顶边。
4. 宠物站在顶边时缓慢移动记事本，确认宠物连续跟随；再最小化或关闭记事本，确认宠物立即坠落且不悬空。

## 双屏拖动怎么测

1. 打开“设置 → 系统 → 屏幕”，点击“标识”，确认 1、2 号显示器，并让两个屏幕在排列图里相邻。
2. 第一轮可让两屏都为 100%；混合 DPI 轮次再把一块设为 100%，另一块设为 125% 或 150%。更改后无需重启宠物。
3. 在屏幕 1 抓住宠物身体，把鼠标和宠物一起穿过两块屏幕之间的接缝，直到**整个可见角色**进入屏幕 2，再松手。这里的“跨屏拖动”不是拖动应用窗口。
4. 在屏幕 2 右键宠物，打开尺寸面板，从当前尺寸改到另一个档位。预期：角色脚底中心（bottom-center）基本停在原处，角色完整留在屏幕 2 的可用区域，不跳回屏幕 1。
5. 从屏幕 2 拖回屏幕 1 再做一次。若两屏上下错位，也要从真实相连的边缘通过，不能从排列图中不存在的区域跨越。

混合 DPI 轮次使用以下命令，让双屏结论也写入结构化证据：

```powershell
powershell -ExecutionPolicy Bypass -File .\Windows统一验收.ps1 -ExpectedDpiPercent 100 -ManualProfile mixed
```

上例要求宠物启动在 100% 的显示器；如果它默认出现在 125% 或 150% 的显示器，就把参数改成对应数值。人工步骤仍需把宠物完整拖过接缝，在另一块不同缩放的屏幕上改变尺寸。

双屏异常建议录制包含两块屏幕的完整桌面，并说明两块屏幕各自的缩放比例和哪一块是主屏。

Windows 实机结果只有在对应 `result.json` 全通过、人工项完成且证据已保存后才能标记通过。macOS 预览、单元测试和 ZIP 静态检查不能替代该结论。

## 回传证据复核

把整个 `acceptance-evidence-时间` 目录带回开发电脑，不要只复制 `result.json`。在仓库目录运行：

```bash
npm run check:windows-evidence -- "<本轮候选.zip>" "<acceptance-evidence-时间目录>" --windows 11 --dpi 100 --manual core
```

Windows 10 轮次把 `--windows 11` 改为 `--windows 10`；125%/150% 轮次相应修改 `--dpi`；混合 DPI 双屏轮次使用 `--manual mixed`。一小时长稳结果额外加 `--soak 60`。复核器会重新读取候选 ZIP，比较实际 EXE、manifest、验收脚本、Windows 代际、DPI、逐项结果、截图、人工记录、采样数量和时间覆盖；缺文件、失败项、候选错配或“只写了 60 分钟但实际时间不足”都会拒绝。

所有轮次收齐后可一次检查完整矩阵：

```bash
npm run check:windows-matrix -- "<本轮候选.zip>" \
  "<win10-100证据目录>" "<win10-125证据目录>" "<win10-150证据目录>" \
  "<win11-100证据目录>" "<win11-125证据目录>" "<win11-150证据目录>"
```

阶段通过需要同一候选覆盖 Windows 10/11 各自的 100%、125%、150% 六个核心组合，其中至少一轮使用 `mixed` 完成混合 DPI 双屏人工项，至少一轮包含经采样时间复核的 60 分钟长稳。mixed 与长稳可以由六个核心轮次中的某一次同时满足；无需为了凑数量重复运行。
