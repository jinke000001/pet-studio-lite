# Phase 6 PRD：桌宠制作台 MVP

## 问题

现有运行、导入、预览与构建能力主要通过命令行使用。内部制作人员必须理解目录、参数、产品 selector、构建目标和平台证据层级，操作不够连贯，也难以在长任务失败后恢复。

## 成功标准

- 普通内部制作人员无需终端即可创建和恢复制作项目。
- 可通过引导完成目录、ZIP 或 Petdex slug 导入、安全校验、动作与真实桌宠预览、产品配置和导出。
- 长任务在后台运行，界面保持响应；失败保留证据并给出中文修复建议。
- 标准宠物包、项目备份包和双平台未签名候选继续版本化、非覆盖、可追溯。
- UI 明确区分导入成功、候选生成和真实 Windows installed-mode 验收。
- 现有五个桌宠运行行为和 Phase 1–5 证据不退化。

## 范围

包含：首次使用引导、制作项目创建/保存/恢复、目录/ZIP/slug 导入、安全校验、联系表与动作预览、真实桌宠预览、产品配置、标准包/项目包/候选导出、任务进度/日志摘要/安全重试，以及中文错误说明。

不包含：AI 从原图生成完整动作、逐帧编辑器、绘画工具、登录、云同步、商城、支付、DRM、正式签名、公证、自动更新或商业发布。第一版“制作”仅指导入已有素材包或图集后完成检查、预览、配置和导出。

## 约束与边界

- 工作台使用独立窗口和入口，不把管理界面放入透明桌宠窗口。
- `src/main.js` 与现有桌宠 runtime 保持独立；导入和构建逻辑从现有模块复用，不在 UI 重写。
- renderer 保持 sandbox、context isolation、无 Node 权限；文件与构建操作只通过受控、校验过的 IPC。
- 原始来源、用户 Codex/Petdex 宠物目录、历史候选、批准素材和 RETURN 保持只读。
- 所有项目与产物继续使用版本化非覆盖目录；macOS 候选不能替代 Windows installed-mode 验收。
- 工作台前端采用 React + TypeScript；Codex 负责契约、逻辑、安全、集成和验证，Kimi 负责 Phase 6.5 的视觉与展示层。

## 初步架构

- `Workbench UI`：项目与步骤展示；Phase 6.5 由 Kimi 完成视觉收口。
- `Workflow Orchestrator`：步骤状态、项目恢复、错误和任务状态。
- `Import / Preview / Product / Export Module`：复用并封装现有能力。
- `Job Runner`：后台执行长任务，提供进度、取消、失败与重试。
- `Workspace Store`：保存制作项目、历史记录和版本化产物。

## 分阶段计划

### Phase 6.1：工作台契约与壳层

- 定义制作项目、步骤状态、任务状态、错误和产物契约。
- 新增独立工作台入口和安全窗口。
- 建立项目工作区与非覆盖保存、关闭后恢复规则。
- 准备 Kimi 页面清单、字段规则、状态矩阵、错误示例和模拟数据交接包。
- 验收：工作台可启动、创建项目、关闭后恢复；现有五个桌宠测试与运行入口不受影响。

### Phase 6.2：第一个完整闭环

- 本地目录/ZIP 导入向导、校验结果、修复建议、联系表、动作预览及真实桌宠启动/停止。
- 验收：不用终端完成“导入 → 检查 → 预览”，v1/v2 合法样本通过，危险 ZIP 仍被拒绝。

### Phase 6.3：产品配置与导出

- 产品身份和平台表单、安全默认值、冲突检查、标准包/项目包/候选导出、日志摘要与 SHA-256。
- 验收：从导入到候选全程无需终端，历史构建不被覆盖。

### Phase 6.4：任务中心与恢复

- 后台进度、取消、安全重试、历史任务、产物定位、项目复制、slug 网络与离线状态。
- 验收：构建期间界面响应，重启后能识别未完成或失败任务。

### Phase 6.5：完整引导与 Kimi 视觉收口

- Kimi 完成页面布局、视觉语言、组件与状态；Codex 接入真实数据和行为并检查无障碍、缩放和减少动态效果。
- 验收：新用户可独立完成主流程，关键错误都有中文说明和下一步动作。

### Phase 6.6：质量门与可运行软件交付

- 完整自动回归、macOS 真实全流程、可运行工作台候选和独立 Windows 验收准备。
- 验收：交付可启动、可操作、可恢复、可导出的工作台候选，不只交付源码。

- Windows 工作台 installed-mode 验收留到 Phase 6.6，不从 macOS 壳层验证推断。
