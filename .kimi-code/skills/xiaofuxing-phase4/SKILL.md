## 分阶段流程

### Gate A：主视觉

1. 先生成一张正面、完整全身、无服装、无道具的主视觉。
2. 背景必须便于稳定抠除；无阴影、地面、光环、文字或场景。
3. 同时提供原尺寸图和实际 `192×208` 预览。
4. 等用户明确确认后才可生成动作。未经确认不得批量展开。

### Gate B：9 种标准动作

按下列帧数分别生成独立横向条带：

- `idle`：6；仅轻微呼吸、眨眼或小幅摆动，不能静止复制。
- `running-right`：8；明确面向屏幕右侧，交替步态。
- `running-left`：8；明确面向屏幕左侧，交替步态。
- `waving`：4；只用手臂动作，不画挥手线。
- `jumping`：5；用身体高度表达起跳、顶点和落下，不画阴影或尘土。
- `failed`：8；用表情和姿势表达失败，不画红叉或漂浮符号。
- `waiting`：6；表达等待用户输入，必须区别于待机和审查。
- `running`：6；表达任务处理中，不得做字面跑步。
- `review`：6；表达专注审查，不添加纸张、放大镜、代码或 UI。

每行都必须：身份一致、完整分离、无遮挡、无跨槽碎片、无文字、无阴影、无漂浮效果、无尺寸突变。逐行做实际 `192×208` 预览，再生成 8×9 联系表和 GIF。等用户确认后才进入方向制作。

不要默认镜像 `running-left`。只有先证明右跑逐帧镜像不会产生跨槽碎片、语义反转或身份变化时才允许镜像；否则独立生成。

### Gate C：方向

1. 先生成并确认四基准方向，固定顺序：`000` 向上、`090` 屏幕右、`180` 向下、`270` 屏幕左。
2. 四个基准必须在正常桌宠尺寸下明确可辨。
3. 再生成两个完整的 8 帧方向条带：
   - row 9：`000, 022.5, 045, 067.5, 090, 112.5, 135, 157.5`
   - row 10：`180, 202.5, 225, 247.5, 270, 292.5, 315, 337.5`
4. 方向在屏幕坐标中定义。眼睛先引导，头部、脸区和上身轻微跟随；脚和下身保持稳定。
5. 不得通过整张角色旋转、倾斜、仿射变形或简单滑动瞳孔伪造 16 个方向。
6. 两行必须各自作为连续整体生成，禁止最后单独拼接一个不一致的方向格。

### Gate D：组装与交接

1. AI 负责视觉生成；精确单格裁切、透明背景、图集组装和验证使用确定性脚本。
2. 可只读参考 `/Users/jinke00001/.codex/skills/hatch-pet/scripts/` 中的现有确定性脚本；运行前检查参数和依赖，不修改这些脚本。
3. 最终必须输出 `1536×2288` PNG/WebP、`pet.json`、联系表、动作 GIF、方向 QA、验证 JSON、SHA-256 和来源清单。
4. 最终包仍是 `internal-test` 候选；macOS 验证不能替代 Windows source、win-unpacked、installed mode 和 100%/125%/150% DPI 验收。
5. Kimi 只提交自己的版本化候选和证据，不宣布取代 Codex 候选；由用户并排比较后决定。
