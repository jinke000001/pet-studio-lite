# 决策点

## D-001 共享内核与单宠导出

- 决定：维护一套共享运行内核，每只宠物只提供标准宠物包和产品构建配置；单宠独立安装包由构建工厂生成。
- 原因：避免为每只宠物复制和维护完整 Electron 工程。

## D-002 Wukong 0.1.9 作为体验参考基线

- 决定：只读复用 Wukong 0.1.9 的透明窗口、拖动、24 FPS 左右跑步、缩放、托盘、随机动作和长待机经验。
- 原因：该版本已有 source、win-unpacked 和 installed-mode Windows 证据。
- 边界：不修改 Wukong 交付目录；通用项目使用新目录和新身份。

## D-003 两种输入共用下游流程

- 决定：输入 A 为 Petdex v1/v2 包；输入 B 为客户提供的角色素材。两者最终统一为标准宠物包并共用运行、构建和验收流程。
- 原因：移植和新素材制作的差异主要在上游，运行与交付应保持一致。

## D-004 客户素材制作最后测试

- 决定：先完成通用内核、Petdex 移植和单宠导出，再加入客户素材制作测试。
- 原因：当前没有客户测试素材，且 AI 动作生成会引入额外视觉变量，不应阻塞基础技术链路。

## D-005 当前暂缓商业发布体系

- 决定：当前不建设收款、订单、账户、DRM、激活码、商店、正式签名、公证和自动更新。
- 原因：项目处于学生试验阶段，优先验证工具和业务需求。
- 保留：产品 ID、版本、来源、作者、授权状态和哈希等低成本兼容字段。

## D-006 原始素材不可原地修改

- 决定：Wukong、Petdex 和客户原始输入都按不可变来源保存；转换、修复和构建使用版本化派生副本。
- 原因：保证回溯、视觉确认和哈希证据可靠。

## D-007 Phase 1 工具链

- 决定：共享内核使用 Electron 43.4.1、electron-builder 26.15.3，项目 Node.js 下限为 22.12.0。
- 原因：Electron 44 刚进入新主版本且已移除 macOS 12 支持；43.4.1 是仍在维护的成熟版本。electron-builder 使用 npm 当前稳定版。
- 边界：Phase 1 只验证 source-mode；Windows/macOS 构建参数和签名策略在 Phase 3 单独确认。

## D-008 产品选择与素材隔离

- 决定：运行器只接受 `config/products/<selector>.json` 中的白名单产品选择器；配置引用被 Git 忽略的 `local-pets/` 工作副本。
- 原因：换宠物无需改核心代码，同时避免修改或提交 Wukong/Petdex 原始素材。
- 边界：正式导入、来源快照和哈希清单由 Phase 2 实现。

## D-009 Phase 2 安全导入与证据格式

- 决定：目录、ZIP 和 Petdex slug 共用同一标准化管线；每次成功导入保存来源快照、标准包、JSON/Markdown 报告、SVG 联系表和离线动作预览。
- 原因：让来源、哈希、运行输入和视觉证据保持同一版本，避免手工复制后无法追溯。
- 安全边界：所有输入均不可信；拒绝链接与路径逃逸，限制数量和体积，使用临时目录加原子改名，输出目录由来源和内容摘要区分且不覆盖。

## D-010 Petdex slug 采用隔离直连适配器

- 决定：不调用会写入 `~/.petdex/pets/` 和 `~/.codex/pets/` 的 Petdex CLI 安装命令；从固定官方清单读取 slug，只接受 `assets.petdex.dev` 的受信清单、JSON 和 WebP，再写入临时隔离目录。
- 原因：满足内部 slug 导入需求，同时保护用户现有宠物目录并复用统一校验与哈希流程。
- 边界：只有 slug 获取阶段需要网络；导入后的标准包和运行器保持离线。

## D-011 Phase 3 候选构建范围

- 决定：Phase 3 生成 Windows x64 `win-unpacked`、未签名 NSIS 候选安装包和 macOS Apple Silicon 未签名 `.app`；不生成 DMG，不执行签名、公证或发布。
- 产品范围：Wukong、Doraemon、阿岱为三个主候选，JokeBear 为额外 v2 内部兼容样本；首轮使用通用测试图标。
- 验收边界：Mac 可完成 source、macOS app 与 Windows 产物静态验证；Windows 真实安装、卸载、重装和 100%/125%/150% DPI 必须在另行授权后完成。

## D-012 Windows 正式验收顺延

- 决定：当前没有 Windows 环境，Phase 3 遗留的 Windows source、win-unpacked、installed mode、卸载/重装和 DPI 正式验收顺延到 Phase 4 完成后统一执行。
- 边界：顺延不改变候选状态；Mac 构建、静态哈希或 Phase 4 完成均不能替代 Windows 正式报告。

## D-013 小福猩身份基准

- 决定：`小福猩素材/307322fa5ca9ee062be71a318055a043.jpg` 是唯一身份基准；默认角色无服装、无道具。
- 固定特征：橙色圆润 3D 软胶/玩具质感、奶白色方圆脸区、棕黑色实体眼睛、小弧形嘴、短手短腿和圆润身体。
- 其他素材：只用于姿势、情绪和侧面结构参考，忽略领带、西装、领结、花和手提包。

## D-014 Kimi Phase 4 独立候选

- 决定：因用户认为当前 Codex 标准动作整体效果一般，保留现有候选作为对照，并允许 Kimi Code 从主视觉开始制作新的 Phase 4 独立候选。
- 隔离：Kimi 使用新的版本化运行目录，不覆盖原始素材、Codex 运行目录、Phase 1–3 产物或用户宠物目录。
- 确认门：Kimi 主视觉、九种动作、四基准方向和 16 方向分别等待用户确认；未确认不得进入下一阶段。
- 工具边界：Kimi Code 可加载 Agent Skills，但项目 Skill 只提供流程；真正的图像生成能力必须在 Kimi 会话中单独确认，不能把 Codex 专属 `$imagegen` 当作已存在能力。
